# Asset library

Everything in the library is **derived, never hand-indexed** — `get_assets`
computes it per request:

- **Scenes** — the images reel.yaml's `stills:` map actually anchors on. Each
  carries `still:<name>` plus `used_by:<scene>` for every scene that
  references it, so a still's downstream is always visible.
- **Characters** — pose pools under `characters/<slug>/`, labelled
  `char:<slug>` and `pose:<file>`. Update a pool and every label that names
  it updates with it.
- **Backgrounds** — location plates under `backgrounds/`, labelled
  `background`. Generated by `reel.py bg <location>` from a `locations:`
  entry (10 seed/prompt variants per run).
- **Custom** — anything the operator drops into `images/`.
- **LORA / Theme** — `themes/<slug>.yaml` descriptors (`slug`, `lora`,
  `trigger`, `labels`).
- **Audio** — rendered music segments plus anything under `audio/`.

`assets.yaml` in the workspace attaches extra labels to any asset (keys are
workspace-relative, or bare filenames for stills in `still_dir`):

```yaml
labels:
  characters/fox_boy/run_.png: [hero, main-walk]
  tony_catch_00006_.png: [char:tony, cond:were-tiger, scene:s5_skydunk]
```

Labels are typed free-form: `char:<slug>` (character), `scene:<slug>`
(foreign key to a scene id), `cond:<x>` (human, were-tiger, …), or any other
tag. The studio's inspector writes them; you can propose them in an
update_yaml-style edit of `assets.yaml`.

Generated images are born `non-verified` (reel.py labels them as they land).
The operator approves (✓ — the label is removed) or deletes (✕ — the file is
gone) on the thumbnail or in the inspector; only non-verified assets are
deletable. When the
operator asks you to clean up a generation run, propose removing the
`non-verified` label on the keepers — deletion is their ✕, not an edit.

Because labels name pools and scenes rather than individual files, refreshing
a character pool and re-deriving is the same operation for you as for a
human: read the labels, regenerate what points at them.

## Rules

1. Anchor scenes with `still:<name>` refs into named library stills — never
   literal paths into `still_dir` when a named still exists.
2. A still that `get_project` shows `present: false` is a broken anchor:
   the file is missing from the pipeline's output dir.
3. New stills come from the wired Qwen generators: `generate kind=still
   slug=<location>` renders a background plate into `backgrounds/`;
   `generate kind=sheet slug=<character>` renders identity sheets into
   `characters/<slug>/` (the pool needs reference images first — the
   operator uploads them via the Characters section's + button);
   `generate kind=image_edit name=<shot>` renders a `shots:` entry's anchor
   stills (10 variants each) into the stills dir. Point `stills:` at the
   variant the operator picks. The pool member tagged `ref` in `assets.yaml`
   is the identity every shot uses.
